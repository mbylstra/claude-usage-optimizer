# Autonomous work queue. Copy this to prompts.txt, which is gitignored:
#
#   cp prompts.example.txt prompts.txt
#
# Sections are separated by a line of three or more '=' characters. Each section
# is:
#
#   STATUS: todo | completed | error | draft | unmerged:<branch>
#                                              (required, first line of the section)
#   REPO: ~/path/to/project                    (optional — see below)
#   <everything else is the prompt, and may span multiple lines>
#
# With no REPO line the prompt gets a brand-new repository of its own, created
# and 'git init'-ed under the new-projects folder set in the extension's
# Settings screen (~/code by default) and named after the date and the prompt.
#
# The scheduler runs the first 'todo' section and rewrites its status to
# 'completed' (exit 0) or 'error' (anything else). Re-queue a failed item by
# editing its status back to 'todo'.
#
# 'draft' is never picked up — it's for a prompt you're still writing and don't
# want run yet. Change it to 'todo' when it's ready.
#
# 'unmerged:<branch>' is written by the scheduler when a prompt finished but left
# its work on a branch instead of merging it — usually because the run had a
# question it couldn't answer for itself. It is skipped like 'draft': review the
# branch it names, then mark the entry 'completed', or put it back to 'todo' with
# the answer written into the prompt.
